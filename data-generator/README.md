# WMS — Генератор данных



Отдельное приложение для создания тестовых файлов и **полной загрузки склада** в WMS.



## Быстрый старт (как запустить)



### 1. Поднять WMS (если ещё не запущен)



Из каталога `wms/`:



```bash

docker compose up -d

```



Проверка: http://localhost:8000/api/health  

Вход в веб-интерфейс: http://localhost (логин по умолчанию `admin` / `admin123`).



### 2. Запустить генератор (веб)



В **новом** терминале:



```bash

cd C:\Users\Darwin\Desktop\Project2\wms\data-generator

python -m http.server 8765

```



Откройте в браузере: **http://localhost:8765**



> Нужен Python 3 только для локального HTTP-сервера. Сам генератор работает в браузере (ES-модули); файл `index.html` напрямую может не открыться из-за ограничений браузера.



### 3. Типовой сценарий для прогнозирования



1. Вкладка **«Полный склад»** (или **Товары** + **История спроса**).

2. В блоке **«Подключение к WMS»** укажите `http://localhost:8000`, логин/пароль.

3. Пресет спроса: **«Бенчмарк прогнозов Супер»** (рекомендуется), **«Бенчмарк»** или **«Нерегулярный»** — не «Стабильный», если нужны правдоподобные MAE/RMSE.

4. При необходимости откройте **«Расширенные параметры»** на вкладке «История спроса».

5. **«Загрузить в WMS»** (полный склад) или **«Только история → WMS»**.

6. В WMS: **Прогнозирование** → ⋮ → обучить XGBoost (если нужен ML) → построить прогноз / валидация.



### 4. CLI (без браузера)



```bash

cd C:\Users\Darwin\Desktop\Project2\wms\data-generator

pip install -r requirements.txt



# История спроса (сложный ряд для сравнения моделей)

python generate_history.py --preset ml_benchmark -n 365 --sku SKU-001 --sku SKU-002 -o demand_history.json



# Полный набор заказов/товаров (см. generate.py --help)

python generate.py products -n 20 -o products.xlsx

```



Импорт `demand_history.json` в WMS: **Прогнозирование** → ⋮ → **Импорт истории**.

## Вкладка «Полный склад» (рекомендуется)



Одна согласованная генерация:



- категории и **товары**;

- сетка **ячеек**;

- **приёмки, перемещения между зонами, расходы и инвентаризации** по расписанию;

- **дневной спрос** для ML (те же SKU, что в каталоге).



Кнопка **«Загрузить в WMS»** → `POST /api/warehouse/bootstrap`.



По умолчанию пресет спроса — **«Бенчмарк прогнозов»** (не идеально стабильный ряд).  

Галочка **«Свои параметры спроса»** — взять все настройки с вкладки **«История спроса»** (включая расширенные).

**Перемещений в месяц** — симуляция переноса остатков из «переполненных» зон в пустые; в WMS пишутся записи `MOVE_STOCK` (раздел **Перемещения**). Товары при старте распределяются по зонам round-robin, чтобы все зоны участвовали в приёмках и переносах.



### Ошибка «failed to fetch»



1. Backend запущен: `docker compose up -d backend` → http://localhost:8000/api/health  

2. URL в форме: `http://localhost:8000` или `http://localhost`  

3. После смены `CORS_ORIGINS` перезапустите backend.



При истории > 40 000 записей загрузка идёт частями автоматически.

## История спроса и настройка «сложности» для ML



Стабильный пресет даёт слишком хорошие метрики у всех методов. Для диплома/сравнения моделей используйте:



| Пресет | Зачем |

|--------|--------|

| **Бенчмарк прогнозов Супер** | Реалистичный микс нерегулярности и пиков (по умолчанию) |

| **Бенчмарк прогнозов** | Сбалансированная сложность |

| **Нерегулярный** | Всплески, провалы, смена тренда |

| **Редкие пики** | Резкие всплески на спокойном фоне |

| **Стабильный** | Только если нужен «лёгкий» ряд |



### Базовые параметры



| Параметр | Описание |

|----------|----------|

| Средний спрос / день | Базовый уровень |

| Тренд (+/− в день) | Линейный рост или спад |

| Шум, % | Случайные колебания |

| Сезонность месяца | Синус по месяцу |

| Множители выходных / праздников | Календарь |

| Вероятность нулевого дня | Дни без расхода |

| Дни недели Пн–Вс | Отдельные множители |



### Расширенные параметры (блок внизу вкладки)



| Параметр | Описание |

|----------|----------|

| Вероятность всплеска / множитель | Редкие «пики» спроса |

| Вероятность провала / множитель | Резкие просадки |

| Вероятность выброса | Отдельные аномальные дни |

| Автокорреляция шума (0–0.9) | Зависимость дня от предыдущего (сложнее для MA) |

| Смена тренда | Случайный перелом ряда в середине периода |

| Разброс SKU мин–макс | Разный масштаб спроса по артикулам |

| Противоположный тренд у части SKU | Гетерогенный каталог |



### Экспорт и загрузка



1. Товары в WMS (полный склад или импорт с вкладки «Товары»).

2. Сгенерировать историю → `demand_history.json` или кнопка в WMS.

3. **Прогнозирование** → импорт → обучение → прогноз / диагностика метрик.



API: `POST /api/predictions/history/import` (менеджер/админ).



Формат:



```json

{

  "comment": "Синтетическая история",

  "records": [

    { "sku": "SKU-001", "date": "2025-01-15", "quantity": 12 }

  ]

}

```



### CLI истории (расширенный)



```bash

python generate_history.py --preset ml_benchmark -n 365 --sku SKU-001 --sku SKU-002 -o demand_history.json



# Тонкая настройка поверх пресета

python generate_history.py --preset irregular -n 400 --noise 40 --autocorr 0.5 --spike-chance 0.1 -o hard.json

```



Список пресетов CLI: `xgboost_wins`, `ml_benchmark_super`, `ml_benchmark`, `irregular`, `spiky`, `volatile`, `stable`.

**`xgboost_wins` («Выйграет Бустинг»)** — ~900 дней, пятничные пики и сентябрьская сезонность; рассчитан на глобальный XGBoost с log-целевой и регуляризацией. После загрузки склада выполните **Обучить все** и сравнение в диагностике.
